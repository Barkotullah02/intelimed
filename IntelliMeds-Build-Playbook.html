How to use this + who builds what

Division of labour. You build in the Figma UI directly (no rate limit there — much faster). My auto-loop is throttled to ~1 screen per 20 min, so treat it as backup only. To avoid duplicate frames: as you finish a screen, tick it here and I'll skip anything already ticked when my loop wakes. If you'd rather I stop the loop entirely, just say so.

Golden rules. Everything uses Inter. Pull fills from the Color variables and text from the shared text styles — never type raw hex. Web screens are 1280 × 832 frames; mobile is 390 × 844. Reuse the existing components (Button, SeverityBadge, SearchField, NavItem, TabBar) as instances.

01

Figma basics — the screen you’re looking at

Read this once, then refer back

Figma runs in your browser or the desktop app. Open the file IntelliMeds — Product Design from your Figma home. The window has five areas — here’s what each one does.

Toolbar top

Tools + the Move arrow (V). The menu (top-left) has everything else. Zoom % is top-right.

Pages top-left

Click the file name area to see the 3 pages: Design System, Web & Admin, Mobile App. Screens live on the last two.

Layers left

The tree of everything on the page — every frame, text and shape. Click to select; double-click a name to rename.

Assets left tab

Next to Layers. Your components (Button, SeverityBadge, TabBar…) live here — drag them onto the canvas to use them.

Design panel right

The most important panel. With something selected it shows position, size, Fill (color), Stroke (border), Effects (shadow), corner radius, and Typography.

Canvas middle

The infinite workspace. Scroll to pan, ⌘/Ctrl + scroll to zoom, Shift+1 to fit everything on screen.

The one idea that makes Figma click: everything is a layer, and layers nest inside frames. A screen is just a big frame with smaller frames (cards, rows, buttons) inside it. A component is a reusable master; when you drag one out you get an instance (a linked copy). Edit the master → every instance updates. You’ll mostly place instances and duplicate frames — not draw from scratch.

02

The moves you’ll repeat

Ten actions cover ~90% of the build

1Open a page & frame a screen

  1. Switch to the Web & Admin page (Pages list, top-left).
  2. Press F (Frame tool). In the right panel’s size boxes type W 1280 · H 832.
  3. Click once on empty canvas to drop the frame. Double-click its name in Layers and rename it, e.g. Web / Dashboard.
Tip: leave ~80px gaps between frames so screens don’t touch.

2Reuse the shell by duplicating

  1. Once your Dashboard (with sidebar + topbar) looks right, click it in Layers to select the whole frame.
  2. Press ⌘/Ctrl+D to duplicate, or hold Alt and drag it aside.
  3. Rename the copy, then just swap the main content — the sidebar & topbar are already there.
Why: this is the fastest path. Build the shell once, duplicate for all 6 other logged-in screens.

3Auto layout (stack things neatly)

  1. Select the items you want stacked (or an empty frame).
  2. Press Shift+A. They snap into a row/column.
  3. In the right panel set direction (↓ vertical), gap (e.g. 16), and padding. Change gap instead of nudging things by hand.
Use it everywhere: cards, rows, nav, forms. It keeps spacing consistent and reflows when text changes.

4Add & style text

  1. Press T, click, and type (e.g. “Interaction Checker”).
  2. With it selected, open the Typography section (right panel) → click the style icon (⋮⋮ / four dots).
  3. Pick a shared style like Heading/H1 or Body/Base. Don’t set size by hand — use the styles.

5Apply a color (from variables)

  1. Select a shape/frame/text. In the right panel find Fill (for text it’s the text color).
  2. Click the color swatch, then the library/variable icon (four dots ⋮⋮) at the top of the picker.
  3. Choose a token — color/brand/primary, text/primary, severity/major, etc. Never type a raw hex.
Border & shadow: use Stroke for a 1px border/default line, and Effects → pick the Shadow/sm style.

6Place a component instance

  1. Open the Assets tab (left). You’ll see Button, SeverityBadge, SearchField, NavItem, TabBar.
  2. Drag one onto your frame — or press ⌘/Ctrl+⇧+K / use quick-insert.
  3. To edit its text, double-click into the instance and retype the label.

7Swap a variant (e.g. severity)

  1. Select a component instance (single click).
  2. In the right panel you’ll see its properties — e.g. Style for Button, Level for SeverityBadge.
  3. Change the dropdown: Level = Major → Moderate turns the badge orange automatically.

8Round corners, borders, shadows

  1. Select a frame. In the right panel set Corner radius (cards 16, buttons 14, pills 999).
  2. Stroke → add, set 1px, color border/default for card outlines.
  3. Effects → “+” → switch type to the Shadow/sm or Shadow/md style.

9Align, group, rename

  1. Select 2+ items → use the align buttons (top of right panel) to center/distribute.
  2. Group with ⌘/Ctrl+G. Prefer auto layout over groups when things stack.
  3. Rename layers as you go — future-you (and clean handoff) will thank you.

10Save, undo, preview

  1. Figma auto-saves to the cloud — no save button needed.
  2. ⌘/Ctrl+Z undoes anything; nothing you do is permanent.
  3. Press ⇧+Space or the ▶ Present button to preview a screen full-size.
03

Worked example — build “Interaction Checker”

Do this once; every screen follows the same rhythm
  1. Frame it. On the Web & Admin page, press F, set 1280×832, drop it, rename Web / Interaction Checker. Set its Fill to color/bg/canvas (paper).
  2. Bring the shell. Duplicate your finished Dashboard frame (move #2) and rename it — you now have the sidebar + topbar for free. In the sidebar, set the Interaction Checker NavItem instance to State = Active and Dashboard back to Default.
  3. Fix the topbar text. Title → “Interaction Checker” (Heading/H1). Subtitle → “Add medications to check for interactions” (Body/Base, text/secondary).
  4. Delete old content. Remove the Dashboard’s stat cards/panels from the main area, leaving the padded content column (an auto-layout frame).
  5. Add the search card. Draw a frame, Fill bg/surface, radius 18, 1px border/default, Shadow/sm, padding 24. Give it vertical auto layout (move #3), gap 16.
  6. Drop a SearchField. From Assets, drag a SearchField instance into that card. It already says “Search medications…”.
  7. Add med chips. Make a small horizontal auto-layout frame (gap 8). Inside, add pill frames (radius 999, Fill bg/soft, padding 8×14) each with a label like “Warfarin” + a small “✕”. Duplicate for “Aspirin”, “Lisinopril”.
  8. Add the action. From Assets, drag a Button, set Style = Primary, label “Check interactions”. Make it full width (select it → set horizontal resizing to Fill).
  9. Add a helper panel. Beside/below, a second surface card titled “How it works” (Heading/H3) with three short steps in Body/Base.
  10. Tidy spacing. Confirm the content column’s auto-layout gap is 28 so sections breathe. Nudge nothing by hand.
  11. Review. Press ⇧+Space to preview. Compare against its blueprint card in the “Web · Patient screens” list below.
  12. Tick it off. Mark “Interaction Checker” done in this playbook so my background loop skips it.
That’s the whole rhythm: frame → duplicate shell → set the active nav → swap the title → build the content from surface cards + component instances + auto layout, all colored from variables. Every remaining screen is a variation on these steps.

Main — remaining 1032px, paper bg, 40px padding. Topbar row = page H1 + one‑line muted subtitle on the left, 44px avatar (teal ring) on the right. Content stacks below with 28px gaps. Duplicate the Dashboard frame as your template for the other web screens — the shell comes for free.
